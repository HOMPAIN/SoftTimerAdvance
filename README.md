# SoftTimerAdvance

Библиотека программных таймеров для Arduino. Помогает организовать работу программы во времени без `delay()`: функция просто добавляется в менеджер, и он сам вызывает её в нужный момент.

Главная цель библиотеки — простота. Базовое использование занимает три строки, а расширенные возможности не мешают, пока они не нужны.

## Возможности

- **Таймеры** — функция вызывается с заданным периодом
- **Отложенный запуск** — функция вызывается один раз через заданное время
- **Таймауты** — функция вызывается, если чего-то не произошло за заданное время
- **Задания (псевдопотоки)** — функция с паузами, которая не останавливает остальную программу
- **Работа из прерываний** — управление таймерами из обработчиков прерываний
- **Сон** — менеджер сообщает, сколько времени осталось до следующего таймера
- **Телеметрия** — время работы функций, загрузка процессора, контроль зависаний

Время можно задавать в микросекундах, миллисекундах и секундах. Библиотека не использует динамическую память и не привязана к платформе: ей нужно только текущее время. Примеры собираются под Arduino Uno и ESP32.

## Быстрый старт

Полный скетч, который раз в 500 мс выводит сообщение:

```cpp
#include "SoftTimerAdvance.h"

uint8_t t_buff[1024];   // Буфер для хранения таймеров
SoftTimerManager ST;    // Менеджер таймеров

// Функция таймера
void Timer500ms()
{
  Serial.println("500ms");
}

void setup() {
  Serial.begin(115200);
  ST.Init(t_buff, sizeof(t_buff));  // Инициализация менеджера
  ST.AddTimer(Timer500ms, 500);     // Таймер с периодом 500 мс
}

void loop() {
  ST.Update(millis());              // Работа менеджера, здесь вызываются таймеры
}
```

Всё использование сводится к трём шагам:

1. Создать буфер и менеджер, вызвать `Init`.
2. Добавить таймеры.
3. Вызывать `Update` в `loop()` как можно чаще.

## Что умеет библиотека

Ниже — короткие фрагменты. На каждую возможность есть отдельный пример, список в конце.

### Таймеры

```cpp
ST.AddTimer(Func, 500);                      // раз в 500 мс
ST.AddTimer(Func, 3, STUnits::Seconds);      // раз в 3 секунды
ST.AddTimer(FuncWithParam, &value, 1000);    // функция получит указатель на value
```

`AddTimer` возвращает указатель, через который таймером можно управлять:

```cpp
STimer *Timer1 = ST.AddTimer(Func, 500);

Timer1->SetPeriod(1000);   // изменить период
Timer1->Freeze();          // остановить
Timer1->UnFreeze();        // продолжить
Timer1->Reset();           // начать отсчёт периода заново
Timer1->ForceCall();       // вызвать сейчас, не дожидаясь конца периода
Timer1->Delete();          // удалить
```

### Отложенный запуск

Функция вызывается один раз и после этого удаляется из менеджера сама.

```cpp
ST.AddDelayCall(Func, 1000);                 // вызвать через 1000 мс
ST.AddDelayCall(Func, 5, STUnits::Seconds);  // вызвать через 5 секунд
```

### Таймауты

Таймаут срабатывает, если его не сбросили за заданное время. Удобно для контроля связи, бездействия, ожидания ответа.

```cpp
STimeout *Timeout1 = ST.AddTimeout(NoDataFunc, 3, STUnits::Seconds);

Timeout1->Reset();   // запустить или начать отсчёт заново
Timeout1->Stop();    // остановить
```

После создания таймаут остановлен, отсчёт начинается с первого `Reset()`. После срабатывания таймаут останавливается, и его можно запустить снова.

### Задания (псевдопотоки)

Задание — это функция, которая может делать паузы. Пока одно задание ждёт, работают таймеры и другие задания.

```cpp
STTask Task1;

void TaskFunc(STTask* Task)
{
  static int i = 0;       // переменные задания должны быть статическими
  TaskBegin();
  for (i = 0; i < 10; i++)
  {
    Serial.println(i);
    TaskDelay(1000);      // пауза 1 секунда, остальная программа продолжает работать
  }
  TaskEnd();
}

Task1.Start((PrmFuncST)TaskFunc, &ST);   // запуск
```

Задание можно остановить через `Task1.Abort()`, а узнать, работает ли оно, через `Task1.IsRunning()`.

### Работа из прерываний

Обычные методы таймеров вызывать из прерываний нельзя. Для этого есть методы с окончанием `FromISR`:

```cpp
void ButtonISR()
{
  Timeout1->ResetFromISR();
}
```

Такой метод оставляет заявку, которую менеджер выполнит при ближайшем `Update`. Доступны `ResetFromISR`, `StopFromISR`, `FreezeFromISR`, `UnFreezeFromISR`, `ForceCallFromISR`. Добавлять и удалять таймеры из прерываний нельзя.

### Сон между таймерами

`Update` возвращает время до следующего срабатывания таймера в тех же единицах, в которых ему передано время. На это время можно усыпить процессор:

```cpp
uint32_t time_to_next = ST.Update(millis());
if (time_to_next > 0)
{
  // до следующего таймера time_to_next миллисекунд, можно спать
}
```

Ноль означает, что есть работа и спать нельзя.

### Телеметрия

Телеметрии нужно время в микросекундах. В Arduino достаточно указать функцию `micros` после `Init`:

```cpp
ST.Telemetry.GetMicros = micros;

ST.Telemetry.CPULoad;       // загрузка процессора функциями таймеров, %
Timer1->GetWorkTime();      // время работы функции таймера, мкс
ST.Telemetry.PoolUsedMax;   // сколько байт буфера занято таймерами
```

Также можно задать допустимое время работы функции (`WatchDogTime` и `OnWatchDog`) и функции включения и выключения светодиода загрузки (`LedOn`, `LedOff`).

## Что важно знать

**Вызывайте `Update` как можно чаще.** Таймеры срабатывают только внутри `Update`, и за один вызов выполняется одна функция. Долгие функции и `delay()` в `loop()` задерживают все таймеры.

**Размер буфера.** Таймер с периодом до 65535 занимает меньше памяти, с большим периодом — больше. Размер выбирается автоматически.

| Плата | Период до 65535 | Период больше 65535 |
|---|---|---|
| Arduino Uno (AVR) | 14 байт | 18 байт |
| ESP32 | 20 байт | 24 байта |

Буфера 1024 байта на Arduino Uno хватает на 56–73 таймера. Если память нужна под другое, буфер можно уменьшить: `ST.Telemetry.PoolUsedMax` показывает, сколько байт реально занято.

**Проверяйте указатель.** Если в буфере нет места, `AddTimer`, `AddDelayCall` и `AddTimeout` возвращают 0. Пользоваться таким указателем нельзя.

**Указатель на отложенный запуск живёт до срабатывания.** После вызова функции отложенный запуск удаляется, и его указатель становится недействительным. Чтобы использовать один отложенный запуск много раз, включите `SetDeleteProtection(1)` (пример `DelayCall/Reuse`).

**Если функцию не успели вызвать вовремя.** По умолчанию пропущенные вызовы не копятся: таймер вызывается один раз и работает дальше. Если важно общее число вызовов, включите строгий режим: `Timer1->SetMode(STMode::Strict)`. Все режимы показаны в примерах `Timer/Mode...`.

**Период больше 65535 у «короткого» таймера.** Если таймер создан с периодом до 65535, а потом период увеличен выше этого значения, таймер переходит на более крупные единицы с округлением (90500 мс станет 91 с). Чтобы этого избежать, создайте таймер сразу 32-битным: `ST.AddTimer(Func, 500, STUnits::Milliseconds, STResolution::Bits32)`.

**Точность таймеров в секундах — до 1 секунды.** Для точных интервалов задавайте время в миллисекундах.

**Таймеры с периодом в микросекундах.** Для них время в `Update` тоже нужно передавать в микросекундах: `ST.Update(micros(), STUnits::Microseconds)`.

## Что изменилось в версии 2.0.0

Версия 2.0.0 несовместима со скетчами для 1.x в следующих местах:

- `Init` больше не принимает разрешение таймеров: `ST.Init(t_buff, sizeof(t_buff))`. Таймеры на 16 и 32 бита хранятся в одном буфере, 64-битных таймеров больше нет.
- Таймеры по умолчанию не навёрстывают пропущенные вызовы. Прежнее поведение включается через `SetMode(STMode::Strict)`.
- `ForceCell` переименован в `ForceCall`.
- Единицы времени и разрешение пишутся только с префиксом: `STUnits::Seconds`, `STResolution::Bits32`.
- Периоды имеют тип `uint32_t` вместо `uint64_t`.
- У менеджера вместо поля `Count` теперь `Count16` и `Count32`.
- `Update` возвращает время до следующего таймера, `STTask::Start` возвращает код ошибки. Старые вызовы без проверки результата продолжают работать.

## Установка

Скачайте репозиторий архивом и добавьте его в Arduino IDE через «Скетч → Подключить библиотеку → Добавить .ZIP библиотеку», либо скопируйте папку библиотеки в каталог `libraries`.

## Примеры

Примеры сгруппированы по темам, каждый показывает одну возможность.

**Timer — таймеры**

- **Timer/Basic** — базовый пример использования таймеров
- **Timer/ParameterToTimer** — передача параметра в таймер
- **Timer/DynamicAddDelete** — динамическое добавление и удаление таймеров
- **Timer/SetPeriod** — изменение периода таймера
- **Timer/Freeze** — остановка и продолжение работы таймера
- **Timer/Reset** — сброс таймера
- **Timer/ForceCall** — внеочередной вызов таймера
- **Timer/GetDelay** — время до срабатывания таймера
- **Timer/Microseconds** — таймер с периодом в микросекундах
- **Timer/ModeSkip** — режим по умолчанию: пропущенные вызовы не копятся
- **Timer/ModeStrict** — строгий режим: пропущенные вызовы выполняются подряд
- **Timer/ModeRestart** — период отсчитывается от момента вызова

**DelayCall — отложенный запуск**

- **DelayCall/Basic** — базовый пример использования запуска с задержкой
- **DelayCall/Parameter** — отложенный запуск функции с параметром
- **DelayCall/Cancel** — отмена отложенного запуска
- **DelayCall/Reuse** — многократное использование одного отложенного запуска

**Timeout — таймауты**

- **Timeout/Basic** — базовый пример использования таймаута
- **Timeout/Stop** — запуск и остановка таймаута
- **Timeout/SetTimeout** — изменение времени таймаута

**Task — задания / псевдопотоки**

- **Task/Basic** — базовый пример работы с заданиями
- **Task/TwoTasks** — одновременная работа двух заданий
- **Task/StartAbort** — остановка и повторный запуск задания

**Interrupt — управление таймерами из прерываний**

- **Interrupt/TimeoutReset** — сброс таймаута из прерывания
- **Interrupt/ForceCall** — внеочередной вызов таймера из прерывания

**Telemetry — мониторинг производительности**

- **Telemetry/CPULoad** — загрузка процессора функциями таймеров
- **Telemetry/WorkTime** — время работы функции таймера
- **Telemetry/WatchDog** — контроль слишком долгих функций
- **Telemetry/LoadLed** — светодиод загрузки процессора
- **Telemetry/PoolUsage** — сколько памяти буфера занимают таймеры

**Sleep — ожидание и сон между таймерами**

- **Sleep/Delay** — время до следующего срабатывания таймера
- **Sleep/ESP32LightSleep** — сон процессора ESP32 между срабатываниями таймеров
